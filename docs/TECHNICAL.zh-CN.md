# X 清流 · Jev 广告过滤

> 本文保留早期版本的技术说明。0.3.0 已改为显性、可编辑的账号/内容/语义规则，规则与来源样本分开保存；当前行为及隐私范围请以 [README](../README.md) 为准。

Chrome Manifest V3 扩展原型，在 x.com 的时间线、搜索结果、推文详情和回复区折叠广告。无需构建或运行后端。

## 安装

1. 解压 `x-jev-filter-0.1.5.zip` 到一个固定目录；或直接使用本项目的 `extension` 文件夹。
2. Chrome 地址栏打开 `chrome://extensions`，开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的文件夹。
4. 刷新已经打开的 X 页面。
5. 点击扩展图标打开设置。在 [TypeSafe 控制台](https://console.typesafe.ai/) 创建 API 密钥，填入设置页，点击「测试连接」。测试使用固定营销示例，会计入 API 请求数。
6. 在「连接 Jev」区域勾选「用 Jev 识别营销内容」并保存。系统广告默认不勾选，可在广告类别区域手动开启；已有保存的选择会保留。

密钥只保存在 `chrome.storage.session` 会话内存中，退出浏览器后需重新输入。请勿把密钥发到聊天、提交进代码或共享安装包。

更新已有安装：将新版文件覆盖到原扩展目录，在 `chrome://extensions` 点击该扩展的重新加载按钮，再刷新 X 页面和设置页。

## 广告类别（v0.1.2）

设置页可单独勾选：系统广告（X 平台投放广告）、商品推广、付费服务与课程、返佣与邀请推广、私信与群组引流、投资与虚拟币营销、博彩推广、成人服务广告。

- 系统广告本地识别；取消后保留显示，即使开启 AI 也不会再次过滤这类平台广告。
- 其余类别需要开启 Jev。只对勾选类别进行判断，命中任一类别且达到概率阈值才折叠；类别可能重叠，例如商品推广同时包含返佣链接。
- 新闻、普通讨论、批评广告等不因涉及某个主题就被视为广告。实际分类效果仍需真实 API 样本验证。
- AI 广告类别与疑似 AI 创作选项全部取消时不发送浏览内容进行判断；手动连接测试仍可发送固定示例。
- 升级时保留原来的系统广告、AI 开关及显示提示设置；旧配置没有类别字段时默认选中所有 AI 类别，保持原过滤范围。
- 每条推文仍用一次 API 请求判断是否属于选中类别的集合；修改类别会使用不同缓存，可能产生新的请求。模型返回的是选中类别集合的广告概率，不输出具体命中的子类别。

## 当前功能

- 本地识别平台广告容器 `placementTracking` 和 `promotedIndicator`，不依靠正文是否包含“广告”字样。
- Jev 判断文字是否主要用于商业推广或招揽客户；默认概率达到 0.95 才折叠。
- 新增「显示清流已折叠提示」开关，默认开启；关闭后直接隐藏平台广告和 AI 判定的营销内容。重新开启可恢复提示条，关闭过滤可恢复原文。保存后自动应用。
- 提示条开启时可一键恢复原文；当前页面会话记住恢复选择，最多 1000 条。
- 账号白名单同时跳过平台规则与 AI，并避免向 API 发送该账号的文字。
- 只判断屏幕内、当前可见标签页的推文；私信路由跳过。
- 正文和引用文字合计最多 5000 字符；纯图片或视频不送模型。
- SHA-256 内容缓存最多 500 条，有效期 24 小时，仅存会话内存；跨标签页复用判断。
- 全扩展串行请求；每分钟上限 120 次；每日上限默认 1000 次，按本地日期重置。
- 12 秒超时；HTTP 错误、限流、无密钥、无效响应和预算用尽均保留内容显示。失败后进入冷却，避免重试风暴。
- 每日请求数和实际返回的输入 token 数在设置页显示；失败请求也占用本地请求预算。
- 关闭插件过滤后自动展开；卸载或刷新页面也可恢复原页面。

## Jev 接口

按 2026-09-23 查阅的 [TypeSafe 官方 API 文档](https://docs.typesafe.ai/api) 实现：

```text
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <API_KEY>
```

模型为 `jev-latest`，请求使用 `state + questions`，根据勾选类别构造判断条件，通过 `noul` 问题读取 `answers.advertising.noul`。它不是 OpenAI Chat Completions 接口；其他 Jev 网关密钥不能直接使用。端点固定，扩展不会接受网页传入的任意 API URL。

Jev 的 Noul 数值是对命题为真的概率估计，不等于插件实测准确率。提示词位于 `extension/core.js`。调整提示词时也更新 `PROMPT_VERSION`，使旧缓存失效。

## 可行性与边界

这类分类任务适合 Jev，但效果需要使用真实中英文推文评估。官方列出了 [对抗内容、字面理解和上下文干扰等限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)，所以不应把高概率当作绝对正确。

优先关注误杀率。建议人工标注 200–500 条广告、普通讨论、产品体验、免费项目分享、引用广告进行批评、隐晦引流及提示注入样本，先测精确率和漏判情况，再调阈值。当前 0.95 是保守起点，并未经过真实语料校准。

主要局限：

- X DOM 没有稳定的公共约定，平台改版、语言版本或广告容器变化可能导致规则漏判；当前 DOM 选择器只做了模拟结构测试，需要在实际账号页面验收。
- API 返回前会先显示原文，因此可能短暂看到广告。网络延迟或触发预算限制时，部分内容继续显示。
- 只做文字判断，图片内广告、表情暗语、个人主页引流可能漏判。未读取完整对话上下文，可能误判被引用的广告或语义依赖上文的回复。
- 支持浏览器加载后的动态推文及节点复用；未实现“只过滤回复”独立模式。
- `jev-latest` 后续升级可能改变分类表现。正式发布宜在评测后固定模型版本。
- 这是自用 MVP，尚未上架 Chrome Web Store，没有生产监控或共享服务端。

按 [TypeSafe 官网](https://typesafe.ai/) 当日展示的每十亿输入 tokens 42 美元估算，假设每天 1000 条、每条连同提示词 500 输入 tokens、每月 30 天，输入费用约 `1000 × 500 × 30 ÷ 1,000,000 × 0.042 = 0.63 美元/月`。这是条件估算，不是实测账单；实际以服务方计费和账号限制为准。扩展限制的是请求数，不是美元额度。

## 数据处理

开启 AI 后，扩展把当前可见推文的正文与引用文字发给 TypeSafe；可能包括受保护账号中你有权看到的内容。文字本身可能含姓名、联系方式等个人信息。不会主动传送作者账号字段、推文链接、Cookie、私信、图片或视频；若它们出现在正文中，则随正文发送。API 请求不携带浏览器 Cookie。

设置与累计用量存放在 `chrome.storage.local`；密钥、错误状态及哈希判断缓存放在仅可信扩展页面可读的 `chrome.storage.session`。不写入原始推文日志，不内置分析服务。TypeSafe 服务端如何处理请求数据，以其 [隐私政策](https://typesafe.ai/legal/privacy-policy) 为准；本插件不承诺服务端零留存。

Chrome 的设计依据：[跨域网络请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、[扩展存储](https://developer.chrome.com/docs/extensions/reference/api/storage)。

## 疑似 AI 创作内容（v0.1.4）

在广告类别区域、系统广告选项下新增，默认不勾选，升级也不会自动开启。需启用「连接 Jev」中的识别开关。与广告类别独立：即使未选任何广告类别也可使用。一次请求中额外加入 `ai_created` Noul 问题，共用折叠阈值，命中时显示「疑似 AI 创作」。关闭选项会恢复该类折叠内容。

仅判断文字，保守关注明确的 AI 生成声明或明显生成残留，不因文风工整、列表或讨论 AI 就判定为 AI 创作。无法证明实际作者身份，可能误判或漏判，尚无真实样本准确率评测。不做图片或视频鉴定；系统广告仍由独立的系统广告开关控制。
